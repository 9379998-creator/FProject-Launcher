# Задание для агента: установить app_fixed.js и прогнать приёмку фазы 0

## Что это

Файл `app_fixed.js` — это ваш текущий локальный `app.js` (копия с Google Drive от 14.09) плюс 7 точечных правок, сделанных внешним ревьюером (Perplexity). Все правки поверх ВАШИХ изменений (beaconPerf, бесконечная прокрутка, переиспользование индекса) — ничего из вашего не откачено.

## Шаг 1. Установка

1. Закрыть ВСЕ окна лаунчера.
2. Скопировать `app_fixed.js` поверх `app/frontend/app.js` в репозитории `C:\Users\a9379\Documents\Codex\FEngineering_Launcher_v3`.
3. Открыть лаунчер заново, F5 после загрузки. Проверить в DevTools (F12 → Console), что нет ошибок.

## Шаг 2. Что изменилось (для понимания, не для правки)

1. `state.pairless` — новый флаг в состоянии.
2. `openSelectedObject`: добавлен маяк `object-open` (длительность GET манифеста) и логика pairless — если в статистике объекта PDF = 0, индекс пар не строится вовсе, все DWG идут в `DWG_MODEL`.
3. Маяк `pair-index` теперь пишет также `pdf=` и `pairless=`.
4. Три места пересборки индекса (`previewFileDirectly`, `collectPreviewFilesForDisplay`, `renderTree`) теперь guarded флагом `pairless`.
5. `DIFF_POLL_INTERVAL_MS`: 15000 → 600000 (15 секунд → 10 минут). Причина: каждые 15 с фронт спрашивал сервер об изменениях; на живом облаке H: что-то меняется постоянно, и `refreshObjectInPlace` перезагружал дерево под руками пользователя. Это главный подозреваемый в симптоме «дерево зависает на полпути и выбрасывает».

## Шаг 3. Протокол приёмки (проверить и записать цифры)

1. Открытие объекта ЖК МОД: время от клика до полного дерева. В `runtime/logs/render-debug.jsonl` должны появиться записи `perf object-open`, `perf pair-index`, `perf tree-render` — выписать их значения.
2. Показ 100 PDF: время до последней миниатюры.
3. Одиночный DOC на ~35 страниц: все страницы в ленте, клик по N-й показывает N-ю.
4. Двойной клик по файлу в дереве на большом объекте: отклик < 1 с, в логе НЕТ повторной записи `pair-index` (индекс не пересобирается).
5. Объект без PDF (если есть): открытие не медленнее обычного, в логе `pairless=true`.
6. Дать лаунчеру поработать 3–5 минут с открытым объектом: дерево НЕ должно самопроизвольно перезагружаться (diff polling теперь раз в 10 минут).

## Шаг 4. Коммит и пуш

Закоммитить и запушить ВСЁ (ваши несинхронизированные правки + этот файл) в ветку `review/v3.3-updates` отдельными понятными коммитами:
- ваш коммит: instrumentation + ribbon infinite scroll + index reuse (то, что уже было сделано вами);
- коммит с app_fixed.js: `perf: pairless objects, diff poll 15s->10min, object-open beacon`.
