## Что уже работает (не ломать)

1. **Подбор пар DWG→PDF (очередь 1 — готова, коммит `4b3b856`).**
   - Индекс строится один раз при открытии объекта (`openSelectedObject` → `state.pdfPairIndex`), все потребители его переиспользуют.
   - Массовый показ: только точные совпадения имён (папка не важна — пары обычно в соседней папке PDF, это учтено).
   - Среди тёзок (одно имя в нескольких папках) выбирается зеркальный путь (`mirrorScore`, `buildPdfPairIndex` хранит списки).
   - Одиночные файлы сохранили полный нечёткий поиск (~0,2 с — незаметно).
   - Замер на объекте 03_ЖК МОД (2687 DWG × 6195 PDF): **476 мс** (было ~9 минут блокировки окна).
2. **Демон CAD (одна сессия AutoCAD).** `scripts/render_dwg_daemon.ps1` + машинерия в `server.py` (`ensure/kill/submit`). Протокол: job-файлы в `runtime/cache/dwg/daemon/jobs`. Fallback на разовый запуск жив (`dwg_convert_oneshot`).
3. **Гигиена процессов.** Демон добивает transient-сессии `acad.exe /Automation` после каждого задания (до/после с задержкой + по idle). Чужие интерактивные AutoCAD не трогает (защита по PID и флагу /Automation). Проверено: посторонних acad не остаётся.
4. **Кэш.** `runtime/cache/dwg/<key>/` по путь+mtime+размер. Повторный показ — доли секунды. Проверено: 0,3–0,6 с.
5. **Только AutoCAD.** Весь код альтернативных CAD вырезан (коммит `48a0783`): ProgId, плоттеры, проверки, сообщения. Мёртвый `open_dwg_review_copy.ps1`, `tools/dwg_*`, старые доки — не тронуты сознательно.
6. **Открытие нативных программ** — на передний план + во весь экран (оба пункта меню, проверено тестами).

## Три ситуации (схема утверждена пользователем)

### Ситуация 1. Папка в основном парная, единичные сироты — ПОЧТИ ГОТОВО
Осталось:
- [ ] Прогресс CAD-очереди уже показывает имя файла — проверить живьём на папке с сиротами.
- [ ] Нечёткий поиск для одиночек: оставить как есть (работает).

### Ситуация 2. Папка вообще без пар — НЕ НАЧАТО
- [ ] Флаг `pairless`: если в манифесте PDF = 0 (или доля exact-пар в первых ~50 DWG нулевая) — подбор пропускается целиком, все DWG сразу `DWG_MODEL`.
- [ ] Замер поэтапного времени конвертации (открытие / печать / слияние) на 3–5 файлах.
- [ ] По замеру: фоновая преконвертация объекта («подготовить заранее»).
- [ ] Пул из 2 сессий — только при доказанной выгоде, отдельным решением.

### Ситуация 3. Один большой DWG (50 листов) — НЕ НАЧАТО
- [ ] Имена листов сквозняком: демон (`Convert-DwgJob`, карта TabOrder→имя) → сервер (`convertedPdfPath` рядом уже есть) → фронт (подписи миниатюр + виртуальное дерево «Листы»).
- [ ] Синхрон «миниатюра ↔ лист» через существующий канал `revealedPath`/`thumb-reveal` (новыe сущности не нужны).
- [ ] Открытие листа в CAD: `acad.exe /b script.scr` (`_OPEN`, `_LAYOUT _S "Имя"`), fallback — обычное открытие. Проверить на AutoCAD 2024.
- [ ] Поэтапный прогресс печати («лист 17/50»): демон должен писать статус по ходу, сейчас молчит до конца.
- [ ] Открытый вопрос к пользователю: переключать ли лист в УЖЕ открытом AutoCAD через COM — табу или можно.

## Ловушки (проверено кровью, не повторять)

- **Окно держит старый JS.** После каждой правки фронта пользователь обязан нажать F5, иначе тестирует прошлую неделю. Сервер отдаёт файл с диска, рестарт для фронта не нужен.
- **Консоль cp1251.** Кириллица в выводе — крякозябры; в скриптах использовать `ascii()`/`ensure_ascii`, временные файлы — UTF-8.
- **PowerShell 5.1 без BOM читает кириллицу как cp1251** → `render_dwg_*.ps1` обязаны быть с UTF-8 BOM, иначе парсер падает. Проверять `ps_parse_all.ps1`.
- **Висячая запятая в массивах PS недопустима** (чистка CAD-дублей это показала).
- **CRLF в server.py.** Править через байтовые патчеры с `\r\n`, иначе дифф шумит на весь файл.
- **Рестарт сервера сиротит демона.** Порядок: убить демона + его acad по `daemon/ready.json`, потом рестарт сервера.
- **Облако H: живое.** Папки/файлы могут исчезать прямо во время тестов (перекладывают). Тестовые DWG копировать локально в `C:\Users\a9379\AppData\Local\Temp\opencode\daemon_test\`.
- **Не запускать тяжёлый CAD без спроса** — каждая конвертация открывает AutoCAD на машине пользователя.
- Бенчи/пробы лежат в `C:\Users\a9379\AppData\Local\Temp\opencode\` (pair_probe, bench_parity, test_daemon_convert, ps_parse_all): переиспользовать, не писать заново.
