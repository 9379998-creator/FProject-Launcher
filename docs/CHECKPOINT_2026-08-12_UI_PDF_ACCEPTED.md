Дальше нужно не перестраивать основу, а тестировать, ловить баги и постепенно полировать интерфейс.

## Откуда пришли

На предыдущей контрольной точке уже была принята базовая архитектура:

- отдельный чистый Launcher v3;
- локальный сервер на `http://127.0.0.1:8780/`;

Основная задача текущего прохода была не в новом рендере, а в доведении пользовательской логики вокруг дерева, поиска, выбора файлов и просмотра.

## Что было исправлено

### 1. Пустое правое поле на старте

Когда объект не выбран, правая область больше не делится визуально на:

- ленту миниатюр;
- основной viewer;
- служебную пустую заглушку.

В стартовом состоянии справа теперь единое чистое поле.

### 2. Поиск и выбор файлов разведены

Раньше поиск автоматически превращал найденные строки в выбранные. Это мешало выбрать один файл из нескольких найденных.

Теперь:

- поиск только фильтрует дерево;
- найденные строки не маркируются отдельной подсветкой;
- выбранными считаются только строки, по которым пользователь кликнул;
- `Escape` снимает выделение, но не очищает поисковый запрос;
- клик вне дерева снимает выделение, но оставляет результаты поиска.

### 3. `Отобразить` больше не берёт все результаты поиска без выбора

Был старый fallback: если выбор пустой, `Отобразить` брал все видимые строки. После поиска это выглядело как залипшее выделение.

Теперь для отображения нужно явно выбрать файл, папку или использовать форматный фильтр.

### 4. Переход назад из PDF-просмотра

Кнопки навигации в объекте разделены:

- `К объектам` — выйти к списку объектов;
- `Назад` — вернуться из PDF-просмотра обратно в дерево текущего объекта.

Сценарий:

1. открыть объект;
2. найти файл через поиск;
3. выбрать файл;
4. нажать `Отобразить`;
5. посмотреть PDF;
6. нажать `Назад`;
7. вернуться к дереву этого же объекта и продолжить выбор.

### 5. Копирование пути

В дереве у файла или папки при наведении появляется маленькая кнопка копирования.

Она:

- копирует полный путь в буфер обмена;
- не меняет выделение строки;
- не раскрывает папку;
- не запускает отображение.

### 6. Кнопка копирования не должна менять геометрию дерева

После добавления кнопки копирования расстояния между строками и визуальная плотность дерева были возвращены к прежней логике.

Кнопка копирования размещена поверх строки справа и не занимает отдельную колонку дерева.

### 7. Переходы JS/CSS защищены от браузерного кэша

Для `app.js` и `styles.css` используется query-version в `index.html`, чтобы браузер подтягивал актуальные изменения после перезапуска.

## Следующий этап — DWG/PDF

Следующая большая задача: анализ DWG и связка DWG с PDF.

Рабочая идея:

1. Найти пары `DWG ↔ PDF` по смыслу.
2. Желательно добиться правила: парные DWG и PDF должны называться один в один.
3. Для DWG показывать визуальную миниатюру от соответствующего PDF.
4. При открытии крупного просмотра показывать PDF-превью.
5. В крупном просмотре дать действие: `Открыть в DWG Viewer` или открыть в нативной DWG-программе.
6. Сам DWG не нужно заново “изобретать” внутри Launcher: просмотр/редактирование выполняет профильная DWG-программа.

Главная роль Launcher на этом этапе:

- найти нужный чертёж по картинке;
- связать PDF-превью с DWG-файлом;
- быстро открыть DWG в правильной программе.
