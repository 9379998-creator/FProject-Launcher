# Checkpoint 2026-08-12 — DWG/PDF pairing accepted

## Статус

Этап DWG завершён и принят пользователем как рабочая контрольная точка.

Принято:

- DWG-файлы находятся в дереве объекта через фильтр `DWG`.
- Для DWG подбирается PDF-пара, если PDF существует в объекте.
- Для DWG с найденной PDF-парой в viewer показывается PDF-превью.
- Для DWG без PDF-пары показывается пустая карточка `Нет PDF-пары`, но сам DWG остаётся выбираемым.
- DWG открывается в нативной программе Windows через кнопку `Открыть DWG`.
- Открытие DWG работает быстро.
- Ошибок в сопоставлении стало мало; оставшиеся неточности допустимо дорабатывать точечно позже.

## Что было сделано

### Backend

Добавлен endpoint:

```text
POST /api/open-file
```

Назначение:

- принимает путь к исходному файлу;
- проверяет существование файла;
- на Windows открывает файл через системную ассоциацию `os.startfile`;
- не пытается сам быть DWG-viewer.

Launcher не заменяет AutoCAD/DWG TrueView/другой просмотрщик, а помогает быстро найти нужный файл и передать его установленной программе.

### Frontend

Добавлен слой DWG/PDF pairing:

- строится индекс PDF-файлов внутри текущего объекта;
- каждый DWG сравнивается с PDF-кандидатами;
- при совпадении DWG получает PDF-превью;
- при отсутствии совпадения DWG всё равно отображается как элемент без PDF-пары;
- кнопка `Открыть DWG` появляется, когда активная карточка связана с исходным DWG.

### Алгоритм сопоставления

Алгоритм был усилен после пользовательской проверки на реальном блоке `АР2.2.2`.

Теперь используются несколько признаков:

1. Нормализация шифров:
   - `АР2-2-2`;
   - `АР2.2.2`;
   - близкие варианты с разделителями.

2. Отбрасывание служебного шума:
   - `СРП_7`;
   - слово `лист`;
   - часть номерных префиксов;
   - разные разделители `_`, `-`, `.`, скобки.

3. Смысловой хвост имени:
   - после вырезания служебной части сравнивается основное название листа;
   - учитываются длинные совпадающие фразы;
   - учитываются последовательности совпадающих слов;
   - учитывается пересечение смысловых токенов.

4. Жёсткие стоп-правила:
   - разные шифры разделов не связываются;
   - `Часть 1` не должна связываться с `Часть 2`;
   - разные узлы/сечения/части при явном конфликте отбрасываются.

Проверенные примеры:

- `Ведомости отделки помещений — Часть 1.dwg` → `... Часть 1.pdf`;
- `Ведомости отделки помещений — Часть 2.dwg` → `... Часть 2.pdf`;
- `Маркировочный план 16-18 этажей...dwg` → соответствующий PDF даже при отличии номера листа;
- `Маркировочный план технического пространства...dwg` → соответствующий PDF даже при отличии номера листа;
- чужой шифр `АР3.2` не цепляется к `АР2.2.2`.

## Важные UX-решения

- Не писать рядом с PDF лишние дубли `PDF PDF`.
- Для связи DWG/PDF использовать компактный признак связи, не засоряющий расширение файла.
- Для DWG без пары не скрывать файл: пользователь должен видеть, что файл существует, и иметь возможность открыть его в нативной программе.
- Нативное открытие — отдельная кнопка, а не автоматическое действие при каждом выборе.
