# Excel Fast Preview Prototype — первый прогон

## Статус

Изолированный прототип создан. Основной Excel UI Launcher не изменялся.

Исходный код: `tools/excel_fast_preview_prototype.py`.

Он делает только первую принятую ступень:

```text
XLSX/XLSM → единая SheetModel → preview.png + thumbnail.webp → cache
```

## Что сохраняется в SheetModel

- выбранный видимый содержательный лист;
- фактически заполненный диапазон (`used range` по значениям);
- значения с предпочтением сохранённого результата формулы;
- основные цвета, полужирный текст и выравнивание;
- размеры строк/столбцов;
- объединённые ячейки.

Из той же модели впоследствии должны строиться карточка и HTML deep view.

## Наблюдения

- Для всех трёх книг сформирована непустая визуальная карточка.
- Длинная 2 000-строчная книга не превратилась в уменьшенный серый массив:
  видны заголовки, столбцы, типы данных и цветовые акценты.
- Повторный показ уже созданной карточки для длинной книги занимает 19 мс и не
  запускает Excel, не строит HTML и не выполняет повторный parsing.
- Это ещё не приёмка: пользователь должен визуально оценить карточки.

## Исправление читаемости крупной карточки

Пользователь обнаружил ошибку в первом zoom-эксперименте: при большом
разрешении текст выходил за высоту своих ячеек и обрезался. Причина была в
renderer: размер шрифта рассчитывался от ширины итоговой картинки, а не из
исходного Excel-шрифта и высоты строки.

Исправлено в `fast-preview-prototype-v2-cell-fit`:

- используется размер шрифта исходной ячейки Excel;
- он преобразуется из pt в px;
- затем жёстко ограничивается 70% высоты конкретной ячейки.

Проверена крупная карточка 3 600×2 300 px в Chrome: кнопка `100%` показывает
источник без масштабирования, масштаб и режим руки активны. Это не формальный
«DPI Excel»: читаемость определяется реальными пикселями готовой карточки и
соответствием текста геометрии ячеек.

## Пакетная галерея — 10 реальных книг

Создан отдельный HTML-экран `gallery-10.html` в runtime cache. В нём:

- десять готовых миниатюр слева;
- крупная готовая карточка выбранной книги справа;
- щелчок по карточке и стрелки ← / → для перехода;
- никакого запуска Excel, HTML deep view или повторного parsing при навигации.

Проверка в Chrome прошла: в ленте отображаются 10 карточек; при выборе второй
книги крупная готовая картинка подменилась, браузер подтвердил загруженное
изображение. Ссылка локального runtime:

`http://127.0.0.1:8780/cache/excel-fast-preview-prototype/gallery-10.html`

### Честная производительность первого прохода

- 8 из 9 новых книг: примерно 0,46–3,69 с на первичное построение;
- 1 большая книга `00-Накопительная по отгрузочным.xlsx` (3,3 МБ,
  диапазон A1:CV2000) — 38,9 с;
- уже кэшированная книга — 1–19 мс.

Большая книга — подтверждённый узкий случай, а не статистика, которую можно
усреднить и скрыть. До интеграции в Launcher нужно отдельно оптимизировать её
разбор (сначала read-only поиск содержательной области, затем ограниченная
загрузка стилей только этой области) и повторно измерить.

## Ограничения текущего прототипа

- Первая версия поддерживает только `.xlsx` / `.xlsm`; `.xls` будет отдельным
  сравнительным тестом и fallback, а не молчаливым исключением.
- Не отображает вложенные изображения и диаграммы.
- Показывает выбранный лист; контактная карточка нескольких листов ещё не
  реализована.
- Не встроен в Launcher и не заменяет текущий непринимаемый Excel UI.

## Следующее решение пользователя

После просмотра трёх готовых `preview.png` и `thumbnail.webp` нужно решить:

1. достаточно ли такой композиции карточки для первичного выбора книги;
2. требуется ли сначала улучшить правила выбора области/листа;
3. только после этого — делать контактную карточку и пакетный кэш 10–20 книг.
