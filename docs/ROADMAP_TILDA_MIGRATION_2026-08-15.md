# Дорожная карта: перенос сайта alumstroy.com на ferospb.info

**Статус:** черновик к обсуждению.
**Дата:** 2026-08-15.

## 1. Постановка

Источник — сайт компании «Алюмстрой» (ALS): проектирование и монтаж
светопрозрачных конструкций и фасадов. Работает на конструкторе Tilda
(tilda-project-id=7683403) за прокси ddos-guard.

Приёмник — домен ferospb.info, который сейчас уже занят: на нём стоит
nginx/1.24.0 (Ubuntu) и отдаётся оболочка F-Engineering Launcher.
Оболочку с домена убираем.

Цель: статический сайт из экспорта Tilda на VPS, с заменой текстов/брендинга
(название, контакты, логотип и т.п.). Не WordPress, не пересборка с нуля.

## 2. Факты текущей реализации (2026-08-15)

| Что | Где | Как |
|---|---|---|
| Источник | `https://alumstroy.com` | Tilda, заголовки `x-tilda-server`, `x-tilda-imprint`, прокси ddos-guard |
| Страницы | главная, `/company`, `/news`, `/media`, `/contact` | статичные страницы Tilda |
| Приёмник | `https://ferospb.info` | nginx/1.24.0 (Ubuntu), отдаёт оболочку Launcher (Last-Modified 2026-07-14) |
| Экспорт Tilda | Site settings → Export | только на тарифе Business; архив static HTML + images/css/js |
| Динамика Tilda | формы, виджеты, аналитика | после экспорта работают не полностью; формы требуют webhook/перенастройки |
| Атрибуты доменов | alumstroy.com за ddos-guard | DNS/регистратор пользователя — доступность уточняется |

Вывод: технически перенос сводится к «экспорт → архив → nginx → правки →
DNS», но есть три отдельные зоны внимания: (1) тариф Tilda, (2) динамика
(формы), (3) освобождение ferospb.info от оболочки Launcher.

## 3. Ключевые решения

1. **Статический сайт, не движок.** Экспорт Tilda даёт чистый HTML/CSS/JS.
   nginx уже есть на VPS — PHP/БД не нужны.
2. **Домен приёмника — ferospb.info.** Источник (alumstroy.com) остаётся
   в аккаунте Tilda и до переключения DNS продолжает работать; после успешного
   переноса можно либо оставить как архив, либо освободить.
3. **Брендинг — только тексты/замена содержимого.** Дизайн и структура
   не переделываются. Правки вносятся в экспортированный HTML до публикации.
4. **Формы решаются отдельно.** После экспорта статики формы Tilda не имеют
   бэкенда. Вариант A — заменить на обработчик webhook (PHP/скрипт на VPS);
   вариант B — на mailto/Telegram/внешний сервис; вариант C — убрать формы
   временно и добавить контакты статикой.
5. **Откат безопасный.** DNS не трогаем, пока сайт не проверен через hosts;
   оболочка Launcher не удаляется, а выносится/отключается только после успеха.

## 4. Этапы

### Этап 1 — экспорт из Tilda (нужен доступ, выполняет пользователь)

- Убедиться, что в проекте 7683403 все нужные страницы опубликованы.
- Временно поднять тариф до Business (на 1 месяц — достаточно).
- Site settings → Export → Download archive (по страницам или целиком).
- Отдать мне архив (путь к файлу или передача файла).
- Проверить наполнение архива: index.html, подпапки страниц, images/, css/, js/.

Выход: архив статики, полный снимок сайта-источника.

### Этап 2 — подготовка приёмника (VPS)

- Определить VPS, где крутится ferospb.info: IP, доступ (SSH), ОС.
- Сохранить текущую конфигурацию nginx (оболочка Launcher) как резерв.
- Создать новый корневой каталог сайта (например, `/var/www/ferospb.info`).
- Разложить архив; главная страница должна называться `index.html`.

Выход: статика отвечает на VPS по hosts-переопределению, DNS не затронут.

### Этап 3 — брендинг (правки текстов/содержимого)

- Заменить название/логотип «Алюмстрой»/ALS на целевое брендирование.
- Обновить контакты, адрес, телефоны, e-mail, реквизиты.
- Проверить все страницы: `/company`, `/news`, `/media`, `/contact`.
- Убрать/переопределить ссылки на Tilda (значок «Сделано в Tilda», tildacdn.com).
- Вычистить мусор экспорта (лишние скрипты/виджеты), по возможности.

Выход: сайт на VPS выглядит как брендированная версия исходника.

### Этап 4 — динамика: формы и интеграции

- Найти формы (обычно «Заказать звонок»/«Контакты») и решить судьбу:
  - A) webhook-обработчик на VPS (PHP/скрипт) + сохранение заявок в файл/e-mail;
  - B) заменить на Telegram-бот / внешний сервис форм;
  - C) статичные контакты без формы.
- Проверить аналитику (Google Analytics / Яндекс.Метрика / Facebook Pixel) — счётчики
  в статике работают, если ID сохранён.
- Проверить sitemap.xml, robots.txt, meta-теги (SEO) под новый домен.

Выход: интерактив работает в выбранном виде, SEO-база на месте.

### Этап 5 — SSL и публикация

- Настроить Let's Encrypt для ferospb.info (или использовать имеющийся сертификат).
- Обновить nginx: site-root на новую папку, редирект http→https.
- Убрать/переместить оболочку Launcher (по решению пользователя).
- Переключить DNS (если ferospb.info ещё не указывает на VPS) — дождаться
  распространения; TTL предварительно снизить.

Выход: ferospb.info отдаёт новый сайт по https, старый контент недоступен.

### Этап 6 — проверка и приёмка

- Открыть сайт на VPS через hosts-переопределение до переключения DNS.
- Проверить: главная и все подстраницы, формы/контакты, https, мобильная вёрстка.
- Проверить оболочку Launcher: не осталось ли ссылок/ресурсов.
- После переключения DNS — финальная проверка с внешней сети.
- Зафиксировать резерв: архив экспорта + конфиг nginx + старый сайт.

Выход: критерии успеха ниже выполнены.

## 5. Критерии успеха (контрольная точка)

1. `https://ferospb.info` отдаёт брендированную версию сайта «Алюмстрой»
   (статика, https, без 404).
2. Тексты/контакты/логотип заменены в соответствии с заданием на брендинг.
3. Формы (если нужны) либо работают на VPS, либо заменены на выбранный вариант;
   контактные данные доступны на всех страницах.
4. Оболочка F-Engineering Launcher больше не отдаётся на ferospb.info.
5. Исходник на alumstroy.com не сломан: до переключения DNS продолжает работать;
   после — откат возможен за минуты (вернуть DNS/конфиг).

## 6. Что нужно от пользователя

- Поднять тариф Tilda до Business на время экспорта и выполнить экспорт (Этап 1).
- Дать доступ к VPS (SSH/хостинг-панель) для Этапов 2–6, либо выполнять
  команды по указаниям.
- Уточнить целевое название/брендинг для замены в текстах (Этап 3).
- Решить судьбу форм (Этап 4, вариант A/B/C).
