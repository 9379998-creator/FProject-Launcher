## 5. Проверенные подозреваемые (по приоритету)

1. **Старое окно/старый JS.** В журнале есть запросы `firstPageOnly:true` ПАЧКАМИ ПО 8 ВПЛОТЬ ДО ПОСЛЕДНЕЙ МИНУТЫ — такой код в текущей сборке остался только в одном месте, а раньше был везде. Значит, параллельно работает окно со старым кодом. Перед отладкой: закрыть ВСЕ окна и вкладки лаунчера, открыть заново, проверить заголовок окна (туда выводится версия сборки, код добавлен) и повторить. Если симптомы ушли — это было оно.
2. **Сцена не следует за лентой.** После полного рендера при уже установленном `activePageKey` новый показ страницы не вызывается — сцена показывает старый титульник, хотя лента полная. Кандидат №1 на «вижу только первую».
3. **Клик по миниатюре N показывает страницу 1.** Возможные места: замыкание обработчика на объекте страницы, несвежий `activePageKey`, повторный показ с `pages[0]`. Идти от обработчика клика (`createPageThumbElement`, ~2100) вниз по `showPdfPage` с живым дебагом.
4. **Гонки повторных рендеров** (клик-клик-Отобразить): каждый стирает ленту (`replaceChildren`) и стартует заново. Частично прикрыто флагом `activeRenderSig` (~2852) — проверить его сброс на всех путях выхода.
5. **Фоновая проверка изменений** (`startDiffPolling` → `refreshObjectInPlace` → `renderSelectedFiles`): на Google Drive может дёргать перерендер папки и сносить полные наборы обратно в титульники. Проверить частоту в журнале.

## 7. Протокол приёмки

1. Один файл-договор → «Отобразить» → в ленте 35 миниатюр.
2. Клик по 10-й → на сцене 10-я (счётчик «Стр. 10 из 35»).
3. Стрелки от 1-й до 35-й идут внутри договора, метка дерева стоит на договоре.
4. На 35-й стрелка вправо → следующий файл, метка перепрыгивает.
5. Двойной щелчок → весь экран; Esc → возврат в ту же позицию.
6. То же для PDF-документа и для выбора всех DOC папки.
