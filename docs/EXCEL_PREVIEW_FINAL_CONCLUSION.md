# Excel-preview: согласие, несогласие и финальное решение

## Короткий итог

С экспертом согласен по главному: Excel-модуль имеет смысл только как система
**визуального отбора**. Центральная продуктовая цепочка должна быть такой:

```text
папка / объект
  → список Excel-книг
  → визуальные карточки книг
  → клик по карточке
  → крупный интерактивный просмотр того же выбранного листа
  → «Открыть в Excel», если нужно работать с исходником
```

Если убрать карточки или быстрый крупный просмотр, ценность Launcher для Excel
резко падает: пользователь снова вынужден открывать книги по именам в Excel.

## С чем согласен

### 1. Текущий путь нужно остановить до интеграции

Текущий HTML-viewer не принят. Он начал решать вторичную задачу — подробный
просмотр — до доказательства главной: полезна ли быстрая визуальная лента.
Исправлять белые экраны и дальше расширять эту ветку как основной Excel-модуль
сейчас не следует.

### 2. Карточка и крупный просмотр — одна функция для пользователя

Миниатюра должна отвечать на вопрос «похоже ли это на нужную книгу?», а клик по
ней — без перехода в другую программу открывать этот же лист так, чтобы его
можно было прочесть: прокрутить по X/Y, приблизить и сменить вкладку листа.

Это не два разрозненных технических этапа, а одна воронка отбора.

### 3. Нужна единая модель листа

Разбор XLS/XLSX должен один раз сформировать внутреннюю модель:

```text
листы, used range, значения, формулы с сохранёнными результатами,
стили, merged cells, размеры строк и столбцов, скрытые области,
изображения и базовые диаграммы
```

Из этой модели строятся оба представления:

```text
единая модель листа
  ├─ визуальная карточка WebP/PNG
  └─ крупный HTML-viewer того же листа
```

Так миниатюра и крупный просмотр не расходятся по смыслу и оформлению.

### 4. У книги должно быть два уровня визуальной навигации

1. **Карточка книги** — показывает выбранный содержательный лист; для сложной
   многостраничной книги допустима контактная композиция из нескольких листов.
2. **Карточки листов внутри книги** — после выбора книги позволяют перейти к
   конкретному листу до открытия подробного режима.

### 5. PDF не должен быть основным Excel-путём

Для нормальной книги желаемая цепочка:

```text
Excel → parser → единая модель → карточка + HTML-viewer
```

`Excel → PDF → изображение` остаётся fallback для старого, необычного или
слишком сложного файла, который прямой renderer не смог показать приемлемо.

### 6. Univer сейчас не нужен

Univer — тяжёлый путь к второму Excel-редактору. Пока не доказано, что лёгкий
viewer из единой модели не справляется с нужным обзором, добавлять его нельзя.

### 7. Главный KPI — экономия времени человека

Нужно сравнивать не размер HTML и не число поддержанных стилей, а сценарий:

```text
50 реальных книг
  → найти нужные
  → открыть в Excel только действительно нужные
```

Сравниваем время обычного последовательного открытия в Excel и время работы
через Launcher. Если выгода мала, усложнять модуль не нужно.

## С чем согласен не полностью

### 1. «Та же миниатюра должна развернуться» — да по содержанию, не буквально

Миниатюра размером, например, 300×200 px не может стать читаемым крупным
просмотром без потери качества. Поэтому не следует физически растягивать один
маленький WebP.

Правильная формулировка:

> Карточка и крупный viewer строятся из одной модели и показывают тот же лист,
> ту же область и ту же композицию; крупный вид рендерится в нужном разрешении.

Переход должен казаться мгновенным: сначала показывается готовая увеличенная
preview-картинка, затем при необходимости подменяется интерактивным HTML.

### 2. Контактная карточка полезна, но не должна заменить понятный первый лист

Контактная композиция особенно хороша для книг со многими разными вкладками.
Однако первая версия должна сначала уверенно показывать один правильно выбранный
содержательный лист. Контактную композицию надо сделать отдельным тестом, а не
обязательным усложнением первого прототипа.

### 3. Не надо заранее обещать конкретную скорость

«Почти мгновенно» для кэшированной карточки — обязательная цель. Скорость
первого рендера зависит от реальных файлов, parser и renderer. Сначала её надо
измерить на тестовой пачке, затем установить числовой порог приёмки.

## Финальное решение

### Решение A — текущий Excel UI не развиваем

Не продолжаем чинить или расширять текущую интеграцию подробного HTML-viewer до
доказательства нового механизма. Непринятый код не коммитится как завершённый
Excel-модуль и не меняет принятые PDF, DWG, Word и UI-механизмы.

### Решение B — строим отдельный Fast Preview Prototype

Первый прототип не является частью Launcher. Его единственная цель:

```text
одна реальная XLSX-книга
  → выбор первого содержательного листа
  → единая модель листа
  → preview.webp / preview.png
  → показать пользователю результат и время
```

Только если карточка помогает понять тип и содержание книги, расширяем прототип
на пакет файлов.

### Решение C — порядок разработки

1. **Аудит текущего кода без изменений основной логики.** Зафиксировать, что
   можно сохранить из `openpyxl`-разбора, HTML-viewer и старого PDF fallback.
2. **Выбор и проверка parser/renderer.** Отдельно сравнить `.xlsx/.xlsm` и
   `.xls`; не заявлять единый parser до реального теста.
3. **Прототип одной карточки.** Реальный файл → изображение → измерение времени
   → ручная оценка пользователем.
4. **Прототип пачки.** 10–20 реальных книг → фоновая очередь → кэш → повторное
   мгновенное отображение.
5. **Крупный вид.** Из той же модели: сначала большая готовая картинка, затем
   интерактивный HTML выбранного листа.
6. **Интеграция в Launcher** только после приёмки пунктов 3–5.
7. **Сравнение с обычным Excel** на 50 книгах и финальное решение об объёме
   дальнейшей разработки.

## Первые критерии приёмки прототипа

- Карточка не является серым уменьшенным массивом ячеек.
- По карточке можно определить хотя бы класс: смета, реестр, расчёт, график,
  спецификация, пустой или нерелевантный файл.
- Клик показывает тот же лист крупнее без белого экрана.
- Крупный вид пригоден для прокрутки и увеличения.
- Повторный показ из кэша не запускает Excel и не выполняет повторный parsing.
- В случае ошибки отображается понятный fallback и кнопка «Открыть в Excel».

## Что делать прямо сейчас

Следующее действие — **не менять Launcher**, а подготовить и проверить
изолированный прототип одной визуальной Excel-карточки на реальной книге.
Результат для проверки пользователя: готовая PNG/WebP-картинка, время первого
построения и время повторного чтения из кэша.
